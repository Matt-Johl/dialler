Office calls on iPhone, even when the app is closed.

Dialler is an iPhone app and a small call server that runs on your own network. Incoming calls wake the phone over your office Wi-Fi, with no Apple push service, no internet connection and no cloud account.

Features

What it does

  • Rings when the app is closed

    While the phone is on your office Wi-Fi, its Local Push extension keeps a connection open to your server. An incoming call wakes it and rings through CallKit, like any other call.

  • Needs no internet

    Wake-ups, signalling and audio all stay on your network. If the internet connection drops, internal calls carry on.

  • Its own exchange

    The server routes calls between phones by itself, so a PBX is optional.

  • Or alongside your PBX

    Asterisk, Cisco CUCM or any SIP exchange, connected as a trunk or as one registered line per phone. PBX credentials stay on the server; the phone never holds them.

  • Encrypted where it counts

    TLS signalling and SRTP audio between phone and server, and the server's certificate is pinned when the phone enrols.

  • A directory for each phone

    Set it from the console or upload a CSV. Users can add contacts and favourites on the phone; both sides edit the same list.

  • No call records on the server

    Call history stays on the phone. The app talks to your server and nothing else.

  • Audio without transcoding

    Opus between phones, G.722 or G.711 to the PBX, one codec end to end. Media and signalling carry QoS markings.

And the usual: hold, transfer, mute, speaker, keypad and recents.

How it works

One server between your phones and your PBX

A closed app can't keep a SIP registration, so the Dialler server is what your PBX and other phones call. It wakes the right phone, then bridges the call.

  1. A call arrives

    From another Dialler phone or from your PBX, at the server.

  2. The server wakes the phone

    Over the connection the phone's extension already holds. iOS shows the call on the lock screen.

  3. Answer and talk

    The app connects, and the server bridges the call and relays its audio.

The one limit

Phones ring on the Wi-Fi networks you list for them. Away from those networks a phone does not receive Dialler calls. That's by design: it's what lets the whole system run without the internet.

Set-up

Two programs on one machine

dialler-server handles calls. dialler-admin is the web console. Each is a single binary with no runtime dependencies, configured with a few flags.

7443 TCPWake-ups and signalling
5061 TCPSIP over TLS
8080 TCPEnrolment and directory
20000–20100 UDPCall audio
# the call server
dialler-server \
  -public-host 10.0.0.10 \
  -local-domain office \
  -tls-cert server.pem \
  -tls-key server.key \
  -admin-token-file admin-token

# the console, beside it
dialler-admin \
  -server-ca server.pem \
  -admin-token-file admin-token \
  -password-file password

Phones calling each other need nothing more.

# add a PBX as a trunk…
-trunk "sip:pbx.office:5060;transport=tcp"

# plus this, for one line per phone
-pbx-mode lines

Reaching a PBX takes one flag, or two for per-phone lines.

Management

Everything from one web console

  • Add a phone

    Give it an extension and a label. The console shows a QR code.

  • Scan it

    The iPhone Camera opens Dialler, which enrols itself. The code works once, for fifteen minutes; it can also be typed in.

  • Wi-Fi and contacts

    Set the office networks and the directory for each phone. They reach the phone as you save.

  • Replace or revoke

    Revoke a lost phone, or issue a new code for its replacement. The old credential stops working.

  • See what's happening

    Which phones are online and registered, the state of each PBX line, and calls in progress with packet loss and jitter.

Each change affects only the phone it names, and never interrupts a call.
