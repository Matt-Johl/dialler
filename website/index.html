Your office extension, on iPhone. Ringing even when the app is closed.

Most SIP softphones stop receiving calls once iOS moves them to the background. Dialler doesn't. A server on your network wakes the app through Apple's Local Push Connectivity whenever a call comes in.

How it works

The PBX calls the server. The server wakes the phone.

The Dialler server sits between your PBX and the phones. It sends the wake-up when a call comes in, and provides the web console for enrolment, directories and status.

  1. The PBX sends the call to the Dialler server.

  2. The server wakes the phone through Local Push Connectivity, and iOS shows the incoming call.

  3. When answered, the app connects and the server bridges the call to the PBX.

Phones receive calls only on the Wi-Fi networks assigned to them.

Set-up

Two binaries, one machine

dialler-server handles calls and wake-ups. dialler-admin is the web console. Both are single binaries, usually run on the same machine.

7443 TCPWake-ups and signalling
5061 TCPSIP over TLS
8080 TCPEnrolment and directory
20000–20100 UDPCall audio
dialler-server \
  -trunk "sip:pbx.office:5060;transport=tcp" \
  -public-host 10.0.0.10 \
  -local-domain office \
  -tls-cert server.pem \
  -tls-key server.key \
  -admin-token-file admin-token

dialler-admin \
  -server-ca server.pem \
  -admin-token-file admin-token \
  -password-file password

For one registered line per phone instead of a trunk, add -pbx-mode lines.
