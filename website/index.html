PBX extensions on iPhone. Ringing even when the app is closed.

Dialpark is a call server that runs on your network. It connects your SIP PBX to iPhones running the Dialler app, and wakes each phone through Apple's Local Push Connectivity when a call comes in, so calls are answered whether the app is open, in the background or closed.

For Asterisk, Cisco CUCM and other SIP PBXs.

How it works

The PBX calls the server. The server wakes the phone.

The Dialpark server sits between your PBX and the phones. It sends the wake-up when a call comes in, and provides the web console for enrolment, directories and status.

DialparkThe system: the call server and its web console, installed on a machine on your network. Licensed per phone.
DiallerThe iOS app, from the App Store. Each phone is enrolled to one Dialpark server and receives its calls from it.

  1. The PBX sends the call to the Dialpark server.

  2. The server wakes Dialler through Local Push Connectivity, and iOS shows the incoming call.

  3. When answered, the app connects and the server bridges the call to the PBX.

Phones receive calls only on the Wi-Fi networks assigned to them.

Set-up

Two binaries, one machine

dialpark-server handles calls and wake-ups. dialpark-admin is the web console. Both are single binaries, usually run on the same machine.

7443 TCPWake-ups and signalling
5061 TCPSIP over TLS
8080 TCPEnrolment and directory
20000–20100 UDPCall audio
dialpark-server \
  -trunk "sip:pbx.example:5060;transport=tcp" \
  -public-host 10.0.0.10 \
  -local-domain site \
  -http-addr 0.0.0.0:8080 \
  -tls-cert server.pem \
  -tls-key server.key \
  -admin-token-file admin-token

dialpark-admin \
  -server-ca server.pem \
  -admin-token-file admin-token \
  -password-file password

For one registered line per phone instead of a trunk, add -pbx-mode lines.
